# P3 第一批 UX 改善 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 解決使用者回報的四項使用不順：配方清單無法分辨同名配方、等級同步藏在確認框裡、求解完要跳分頁才能複製巨集、預設語系是簡體中文。

**Architecture:** 三項純前端呈現層改動加一項預設值調整。配方清單上方新增一個全域「等級同步」控制項，難度欄依它即時重算——這兩者是同一個機制，因為月球（宇宙探索）的等級同步配方在沒有同步等級時**沒有**確定的難度值。求解分頁直接嵌入既有的 `MacroExporter` 元件，不動巨集產生邏輯。語系預設分介面語言與資料來源語言兩處。

**Tech Stack:** Vue 3 SFC、Element Plus、Fluent（四語系 SFC 區塊）、Pinia。

## Global Constraints

- 只改前端呈現。禁區：全部 Rust crate、`src/datasource/`、`src/libs/` 的 `Craft.ts`/`Solver.ts`/`SolverWorker.ts`/`Analyzer.ts`/`AnalyzerWorker.ts`/`Gearsets.ts`/`Enhancer.ts`、`vite.config.ts`、`docker/`、`docker-compose.dev.yml`、`.github/workflows/`、`versions.json`、`src-tauri/Tauri.toml`、`package.json`。
- **本批已放行的例外**（使用者 2026-08-06 明確同意，僅限本計畫所述用途）：
  - `src/App.vue` — 介面語言 fallback
  - `src/stores/settings.ts` — **僅改資料來源語言的預設值**，不得改 `toJson` 的欄位組成、不得改持久化格式、不得改既有欄位語意
  - 配方清單得額外呼叫 `recipeLevelTable` / `recipeLevelTablebyJobLevel` 以取得難度（原禁止改變 API 請求形狀的限制在此項解除，但**必須依 rlv 去重**，不得每列各打一次）
- **不得新增或移除任何 `invoke()` 或 wasm 呼叫。** 難度一律呼叫既有的 `newRecipe()`（[Craft.ts:268](../../../src/libs/Craft.ts)，純算術、無 wasm），**不得自行複製其公式**。
- 巨集輸出、模擬數值、求解結果一律不得改變。
- 不得改動 `DataSource` 介面本身，也不得改其 optional 成員的 feature-detect 邏輯（`recipeLevelTablebyJobLevel` 是 optional，呼叫前必須檢查存在）。
- 新增文案必須四語系齊備（zh-CN / zh-TW / en-US / ja-JP）。
- 註解用繁體中文；Prettier 4 空格、單引號、arrow function 參數不加括號。
- Commit 訊息用繁體中文，不得有任何 AI 署名。
- 不得改動 P1 建立的色彩 token；需要顏色一律從 `src/assets/theme.css` 既有 token 取用。
- 完成後 `pnpm tsc --noEmit` 必須通過。

### Task 1: 預設語系改為繁體中文

**Files:**
- Modify: `src/App.vue`（`lang` ref 初值與 `watchEffect` 內的 fallback）
- Modify: `src/stores/settings.ts`（`dataSourceList` 的語言順序）

**Interfaces:**
- Produces: 無下游依賴

- [ ] **Step 1: 介面語言 fallback**

`src/App.vue` 目前是：

```js
const lang = ref('zh-CN');
```

以及 `watchEffect` 內：

```js
lang.value = settingLang ?? systemLang ?? 'zh-CN';
```

兩處的 `'zh-CN'` 都改為 `'zh-TW'`。**`settingLang` 與 `systemLang` 的取得方式不動**——使用者已設定的語言、以及跟隨系統的行為都必須保持原樣，只有「兩者都無法決定時」的最終退路改成繁中。

- [ ] **Step 2: 資料來源語言預設**

`src/stores/settings.ts` 的 `dataSourceList`：

```ts
export const dataSourceList: Map<string, DataSourceLangID[]> = new Map([
    ['local', []],
    ['yyyy.games', ['zh-CN', 'zh-TW', 'en', 'de', 'fr', 'ja']],
]);
```

store 的 state 用 `dataSourceList.values().next().value?.values().next().value` 取第一個語言當預設，所以把 `'zh-TW'` 移到最前面：

```ts
    ['yyyy.games', ['zh-TW', 'zh-CN', 'en', 'de', 'fr', 'ja']],
```

**只動這一行的陣列順序。** 不得改 `DataSourceLangID` 型別、不得改 `toJson`、不得改 `loadSettings` 或 `fromJson` 的任何邏輯。

- [ ] **Step 3: 確認既有使用者不受影響**

`fromJson` 會 `$patch(JSON.parse(json))`，已存檔的 `dataSourceLang` 會覆蓋預設值，所以既有使用者的設定不變——只有全新使用者（localStorage 無 `settings.json`）才會拿到新預設。

用瀏覽器 DevTools 驗證：

1. 開 `http://localhost:5173`，Application → Local Storage → 刪除 `settings.json`
2. 重新整理 → 介面與配方名稱都應是繁體中文
3. 到設定頁把資料來源語言改成簡體中文 → 重新整理 → 應維持簡體（證明既有設定不被預設值蓋掉）

Expected: 無錯誤

### Task 3: 配方清單加入等級同步與難度欄

**Files:**
- Modify: `src/components/recipe-manager/RecipeSelector.vue`

**Interfaces:**
- Consumes: `newRecipe`（來自 `@/libs/Craft`，純算術）、`settingStore.getDataSource()`、`RecipeInfo`
- Produces: 無下游依賴

**背景（實作者必讀）：** 月球（宇宙探索）的等級同步配方以 `rlv == 690` 且 `recipe_notebook_list` 落在 1496–1503 或 1528–1535 判定（見 `src/components/recipe-manager/ConfirmDialog.vue` 的 `isDynRecipe`）。這類配方的難度取決於使用者選的同步等級，**沒有同步等級就沒有難度可言**。一般配方的難度則由 `rlv` 決定。

- [ ] **Step 1: 新增等級同步控制項**

在 `RecipeSelector.vue` 的 `.filter-row` 內、`recipe-level` 那個 `el-form-item` 之後，加入第四個：

```html
<el-form-item :label="$t('level-sync')">
    <el-input-number
        v-model="syncLevel"
        clearable
        :min="1"
        :max="100"
        :step="1"
        step-strictly
        :controls="false"
    />
</el-form-item>
```

搭配一個 ref：

```js
// 等級同步：月球配方的難度取決於此值，未填時該類配方的難度欄顯示為「—」
const syncLevel = ref<number>();
```

**這個控制項不觸發搜尋**（不要接 `@change="triggerSearch"`），它只影響難度欄的顯示。

- [ ] **Step 2: 依 rlv 去重取得配方等級表**

新增一個以目前頁面資料為輸入的難度對照表。**必須依 rlv 去重**，且等級同步配方整頁只打一次：

```js
// 難度對照表：key 為 recipe id，value 為算好的難度
// 依 rlv 去重後才取配方等級表，避免每列各打一次 API
const difficultyMap = ref<Map<number, number>>(new Map());

async function loadDifficulties(rows: RecipeInfo[]) {
    const ds = await settingStore.getDataSource();
    const next = new Map<number, number>();

    // 等級同步配方：整頁共用同一個同步等級，只需查一次
    const dynRows = rows.filter(isDynamicRecipe);
    if (dynRows.length > 0 && syncLevel.value != undefined) {
        // optional 成員，必須 feature-detect
        if (ds.recipeLevelTablebyJobLevel != undefined) {
            const rlv = await ds.recipeLevelTablebyJobLevel(syncLevel.value);
            if (rlv != null) {
                for (const row of dynRows) {
                    const r = await newRecipe(
                        rlv,
                        row.difficulty_factor,
                        row.quality_factor,
                        row.durability_factor,
                    );
                    next.set(row.id, r.difficulty);
                }
            }
        }
    }

    // 一般配方：依 rlv 去重
    const staticRows = rows.filter(r => !isDynamicRecipe(r));
    const uniqueRlvs = [...new Set(staticRows.map(r => r.rlv))];
    const tables = new Map(
        await Promise.all(
            uniqueRlvs.map(async rlv =>
                [rlv, await ds.recipeLevelTable(rlv)] as const,
            ),
        ),
    );
    for (const row of staticRows) {
        const rlv = tables.get(row.rlv);
        if (rlv == undefined) continue;
        const r = await newRecipe(
            rlv,
            row.difficulty_factor,
            row.quality_factor,
            row.durability_factor,
        );
        next.set(row.id, r.difficulty);
    }

    difficultyMap.value = next;
}

// 判定是否為等級同步配方，條件與 ConfirmDialog 的 isDynRecipe 一致
function isDynamicRecipe(row: RecipeInfo): boolean {
    const notebook = row.recipe_notebook_list;
    const range1 = notebook >= 1496 && notebook <= 1503;
    const range2 = notebook >= 1528 && notebook <= 1535;
    return (range1 || range2) && row.rlv == 690;
}
```

在 `displayTable` 變動時與 `syncLevel` 變動時各觸發一次：

```js
watch([displayTable, syncLevel], ([rows]) => {
    if (rows != undefined && rows.length > 0) loadDifficulties(rows);
});
```

**注意**：`isDynamicRecipe` 的判定條件與 `ConfirmDialog` 的 `isDynRecipe` 是同一組魔術數字。這是刻意的重複——`ConfirmDialog` 的版本讀 `props.recipeInfo`、這裡讀傳入的 row，兩者無法直接共用而又不得修改 `src/libs/`。**在註解中明確標註兩處必須同步維護。**
